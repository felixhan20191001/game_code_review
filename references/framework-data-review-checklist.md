# 框架集成、界面与数据

只采用当前项目存在的机制。先识别再追踪；公共框架经验不能替代当前版本证据，也不要求项目采用统一的配置、AB 分流或存储设计。

本文件的依赖、UI、存储、配置与埋点审查共同使用 [V1 问题成立前检查](evidence-validation.md#v1-reachability)，核实实际装配、加载、触发和消费条件。

<a id="f1-dependencies"></a>
## F1 依赖、注册与事件传播

- 从实际业务入口定位状态拥有者、初始化、注册／注销、更新调度、事件发送与处理，以及退出／重新初始化的责任。
- 对受影响状态查相关读写方，对事件查发送方与接收方；包含继承、组合、字符串／反射注册、框架回调等间接联系。
- 检查新功能对旧订阅者、旧流程对新状态的影响；公共调度、队列、互斥、共享资源和跨模块派生状态可能扩大影响范围。
- 判断通知同步还是异步、处理顺序、异常传播、重复注册与重入；不能只看事件名字或调用点。
- 比较启动、重新登录、账号切换和重新进入时的初始化路径；按证据判断缓存状态及订阅是否仍对应当前数据。
- 记录已追踪到的依赖边界。无关模块不扩大审查，无法闭合的相关链路作为未覆盖项。

<a id="f2-ui"></a>
## F2 界面生命周期与序列化绑定

- 还原创建、初始化、绑定、打开、显示／隐藏、动画完成、关闭、缓存／回池、销毁的实际顺序，确认每个阶段是否执行及能否重复执行。
- 检查基类钩子、事件订阅、刷新和清理；关闭不一定销毁，隐藏不一定注销，重新打开不一定重新初始化。
- 检查缓存窗口是否收到不该处理的事件、再次打开是否显示旧状态、关闭顺序是否影响队列推进或输入恢复。
- **跨界面跳转与返回一致性：** 对叠加界面中的二次入口，核对跳转方式是否符合当前上下文（切换底层页面或叠加新窗口），目标窗口的显示与输入层级是否一致，返回后是否保留原流程所需状态。同一窗口存在多种打开方式或复用实例时，检查其模式、层级与返回目标是否随本次入口更新；继续业务前确认必要的界面清理不依赖已隐藏或失效的页面，最终可见、可操作界面与业务状态一致。
- 涉及 Unity 时，从真实加载的场景／Prefab／变体追踪引用，检查相关 public／SerializeField 字段、资源映射、按钮事件绑定和必要本地化内容。
- 序列化为空时，继续核对继承、变体覆盖、对象创建及运行时赋值是否发生在使用前；只有能证明使用时缺失且路径可达，才确认空引用缺陷。
- 其他引擎检查等价的场景、实体、资源与绑定机制；不要套用 Unity 或特定消息框架的生命周期。

<a id="f3-storage"></a>
## F3 存储边界、重启与数据替换

- 区分内存写入、标脏、缓存、实际写盘、远端提交和确认；追踪保存函数内部及驱动时机，不以名字或日志判断完成。
- 核对业务状态、资源、领取记录、账号和局次／活动轮次在各存储边界的一致性；跨多份数据时检查实际提交与恢复顺序。
- 重启、重登、账号切换或加载远端数据后，旧对象引用、缓存、订阅与进行中回调是否仍写旧数据或污染新账号。
- 对旧存档、缺失字段和升级迁移核对默认值、保留进度、重建状态及奖励记录；字段或配置含义变化也可能需要兼容处理。
- SDK 移除或升级、混淆／保留规则调整（如 R8／ProGuard）、支付或启动流程变化，均触发升级兼容检查；不能因玩法或存档字段未变而跳过。以玩家实际使用的旧正式版本到兼容新正式包为基线，核对账号、包名、签名及可升级版本条件，保留数据且不卸载、不清数据；新装、同版本重启及卸载后恢复不能代替覆盖升级。
- 按实际受影响链路组合检查：旧包使用 SDK 后留下的数据或配置，在新包首次初始化、首次及后续请求中的处理；旧包已支付未完成订单在新包补单及防重复发货；升级后首次断网启动、权益保留和联网恢复。核对进度、资产、奖励记录及阻塞风险；不适用项简述依据，依赖商店、SDK 或真机的未知行为列为待验证，不直接判定缺陷。
- 不能根据单一保存缺口推断“必丢数据”；核对其他保存入口、中断窗口和真实持久化机制。不足以证明时明确剩余证据。
- 玩家重启和工具强制构造存档不是同一种复现方式，报告时区分。

<a id="f4-config"></a>
## F4 配置来源、消费路径与资源

- 涉及多语言文案、缺字或翻译资源时，按 [多语言专项](localization-review.md) 调用内置只读脚本并补充实际消费链；其他配置审查不自动扫描整张翻译表。

- 仅在相关功能依赖数据时，查明本项目的权威来源、实际读取入口、选择条件、缓存时机、最终消费位置及有效值。
- 有导出或生成机制时联合核对源数据、生成代码／资源和实际加载产物；没有该机制则不假设存在导表步骤。
- 使用当前项目实际规则确认键、索引、单位、阈值和引用关系，不套用其他游戏的表名、结构、读取分支或默认值。
- 按可达输入检查缺失、空、过期、越界或版本不一致时的行为；降级方式须有需求或实现依据，不凭空指定业务策略。
- 配置或资源存在不能证明玩家使用到；检查实际加载／选择路径。缺失某个候选资源也不等于整个功能无法运行。
- 运行数据或远端选择不可见时，说明验证限于哪一版本、数据与分支，以及不能确认的实际生效范围。

<a id="f5-telemetry"></a>
## F5 埋点上报：时机、字段与次数

需求包含埋点、用户要求核对上报，或当前审查的业务路径包含埋点时使用；只扩展到相关事件与上报依赖。诊断日志与业务统计事件分开识别，不将普通日志输出当成埋点已送达。

- **口径与链路：** 依据当前需求／埋点文档确认事件含义、触发条件、统计单位和目标渠道，追踪业务入口、公共封装、SDK 与实际发送路径。事件名、字段结构、采样、过滤及去重规则以本项目为准；缺失或冲突的约定列为待明确，不套用其他游戏规则。
- **触发时机与漏报：** 区分曝光、点击、尝试、业务成功和展示完成；核对上报相对校验、扣除／到账及状态切换的时点。覆盖适用的成功、拒绝、取消、失败、超时与替代入口，检查提前返回、异常或中断是否跳过应报事件，未完成业务是否误报成功。并非每个分支都必须上报，以事件定义为依据。
- **字段取值：** 核对事件名、必填字段、类型、枚举、单位、数量正负及空值／默认值；追到字段真实来源和公共参数合并位置，检查覆盖或沿用旧值。区分操作前后值、增量与总量、事件发生时间与发送时间，核对账号、局次、活动轮次及业务来源是否属于本次事件。
- **异步快照与归属：** 延迟组装或发送时，检查复用字典／对象、闭包及发送时读取当前状态是否改写历史事件；换局、活动换轮、重登或账号切换后，旧回调与缓存事件仍需保持正确归属。是否复制或冻结数据由实际封装／SDK 行为确认，不只看调用处。
- **重复上报：** 按一次点击、一次尝试、一次成功等实际统计单位核对次数；检查连点、重复订阅、界面重开、重复回调、公共封装与业务层、SDK 自动采集与手动上报是否叠加。同一次业务重报与不同业务的合法多次上报分开判断；有事件标识不等于实际去重，也不要求所有事件只报一次。
- **发送与中断恢复：** 涉及队列、批量或重试时，核对入队、发送、确认、清理及必要保存的边界，检查断网、超时、前后台切换、退出与恢复后的漏发或重发窗口。联合确认客户端与接收端的重试／去重约定；采样、过滤或允许丢弃须有依据，未知 SDK 行为列为待验证，不承诺恰好送达一次。
- **业务影响：** 检查字段计算是否带业务副作用，上报异常、同步等待或回调是否中断奖励、存储、状态切换及锁释放；关闭上报后业务流程是否仍按需求执行。高频上报涉及卡顿、队列积压或资源开销时核对频率与执行方式，性能结论须有证据。
- **验证与报告：** 区分调用接口、进入队列、序列化／发送、接收确认和平台入库／统计；逐层标明已验证边界，单条日志或调用成功不能证明最终收数正确。对照同一次业务的状态与实际载荷核对时机、字段和次数；仅有静态代码时给出推导及待验证项，复现和报告使用主文件的[问题报告约定](../SKILL.md#finding-report)。
