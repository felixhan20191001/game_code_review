# 状态机、阻塞与玩法耦合

用于状态切换、时序竞争、等待、暂停、复活、退出及道具效果审查。状态归属、事件顺序和恢复策略从当前实现与需求确认，不预设某种引擎或玩法。

确认状态或玩法问题前使用 [V1 问题成立前检查](evidence-validation.md#v1-reachability)，核实当前模式、事件来源及状态前提。

<a id="s1-states"></a>
## S1 组合状态与状态归属

- 识别显式状态及分散标记：结果、玩法阶段、暂停、输入／移动锁、等待、界面、计时器、临时效果、持久化进度。
- 对相关转换记录：源状态、事件、前置条件、状态拥有者、目标状态、连带变化、竞争写入方及局次／对象身份。
- 核对哪些状态必须同步、哪些可以独立；枚举已切换不能证明输入、计时和表现同时恢复。
- 给各计时器标明时间源、推进／暂停条件、重置和到期处理；不要从“游戏暂停”推断所有子系统都停止。

<a id="s2-ordering"></a>
## S2 事件时序与异步竞争

- 还原更新循环、碰撞、业务事件、UI 生命周期、动画、协程／任务、网络或平台回调之间的真实顺序；必要时追踪框架实现。
- 区分开始处理、业务完成、表现完成、结果提交。多种成功／失败事件竞争时，核对需求中的优先级和唯一结算语义。
- 对延迟工作记录：业务生效时点、执行宿主、取消机制、所属账号／局次／活动轮次、回调前置条件及过期后的处理。
- SDK／原生回调新增排队或跨帧捕获时，补查 [C2 跨语言生命周期](stability-sdk-review-checklist.md#c2-native)；闭包中的托管对象存活不证明其原生句柄有效。
- 检查关闭、暂停、复活、退出、换局、回池或账号切换后，旧回调是否还能修改新状态；对象非空不等于仍属于原流程。
- 同步通知也可能重入、改变后续处理条件或因异常中断分发；不能只检查异步任务。

<a id="s3-recovery"></a>
## S3 阻塞、退出与恢复

对每个等待和不可操作状态核对：
- 谁负责推进或释放，正常完成事件是否一定可达。
- 失败、取消、超时、异常、提前返回、UI／场景关闭时，如何退出或恢复。
- 动画不回调、任务取消、对象销毁、网络无响应时，是否仍存在按需求继续、重试或离开的路径。
- 锁的获取与释放是否按拥有者配对；嵌套流程不能提前释放他人持有的锁，也不能清零后再被旧回调错误减计数。

适用时逐项核对目标状态应满足的条件：

| 转换 | 目标状态检查 |
|---|---|
| 复活／恢复 | 结果、输入、移动和计时正确恢复；保留／重置／追加效果符合原因与来源；旧回调不能再次结束本局 |
| 胜利／失败 | 终局只提交一次；结算快照正确；输入按需求禁用；不重复弹结果界面 |
| 暂停／叠加界面 | 各来源的暂停与锁平衡；界面关闭顺序改变后仍可继续 |
| 重试／退出／换局 | 订阅、延迟工作、对象池、计时及临时标记不污染下一局；离开前的业务记账符合规则 |
| 保护／限时效果结束 | 在竞争结果、提前返回及对象失效后仍完成必要撤销，或由已证实的统一清理接管 |

“没有异常日志”不能证明流程畅通；要证明玩家最终可以到达规定的下一步。是否需要超时及超时行为以业务规则为准，不为每个等待机械要求同一种处理。

<a id="s4-effects"></a>
## S4 效果与玩法耦合

- 对共享能力或属性记录：效果来源、叠加／覆盖规则、持续时间、表现优先级、撤销责任和所属局次。
- 检查 A 后 B、B 后 A、两种结束顺序、同类重复触发，以及暂停、失败、复活、退出时的保留或撤销。
- 证明结束一个来源只撤销其贡献；逻辑能力、数值、动画／特效／音效不能互相矛盾。
- 对混合玩法检查分数、目标、任务计数、资源与结算归属；旧入口不能绕过新规则，新结果不能重复驱动旧流程。
- 从共享状态、时序冲突和损失后果选择代表组合；若第三个事件会改变前两者顺序，补充该组合，不穷举全部道具与模式。

只对已经追踪或验证的状态范围下结论；报告方式与证据标记使用主文件的[问题报告约定](../SKILL.md#finding-report)。
