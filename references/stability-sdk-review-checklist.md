# 稳定性、广告与原生 SDK 边界

用于整体回归的稳定性初筛、广告专项、崩溃／闪退／ANR 和跨语言异步改动。只展开项目实际存在且与审查范围有关的链路；单纯文案／排版修改没有相关依赖变化时，不扩展为全 SDK 审计。严重度与证据状态遵循主文件的[问题报告](../SKILL.md#finding-report)。

<a id="c1-triage"></a>
## C1 先定位高影响路径

- 整体回归先用地图与源码确认启动／首次初始化、外部 SDK 回调、切前后台、全局输入锁与核心流程等待的入口，再检查普通业务。广告专项直接从初始化到退出追踪，不只审查看完广告发奖。
- 固定提交／平台／构建宏与实际 SDK 版本。按审查范围列出关键链路、目标平台、代码已查／运行已验／待查和剩余证据；已核实且未变化的关系复用，不重新穷举所有平台组合。
- 从改动及调用方寻找高影响信号：同步变异步、Post／dispatch／Task／跨帧捕获、IntPtr／DllImport／MonoPInvokeCallback／__bridge、JNI 引用、Dispose／Destroy、初始化顺序、锁与阻塞等待。关键词只是候选；必须还原可达路径和实际平台实现。
- 回调被延迟时，连同未出现在 diff 中的包装类、原生入口、释放方与消费者一起看。比较引入时序变化的历史提交，确认旧路径是否在回调有效期内完成消费；改动少不等于风险低。
- 先区分进程退出、系统低内存终止、ANR／看门狗、全局输入被遮罩、局部动画停止。能退出或重试的局部问题不能直接推成线程死锁。

<a id="c2-native"></a>
## C2 跨语言生命周期与线程

对每条实际跨队列／跨语言链路，填写一条简短证据记录，缺项直接标未知：

| 对象／句柄与产生位置 | 有效期和持有者 | 入队前如何保活 | 消费线程与时点 | 谁在何时释放 | 失败／取消／提前返回如何清理 | 目标平台证据 |
|---|---|---|---|---|---|---|

- 沿“SDK 回调产生对象 → 托管包装 → 排队 → 平台桥接 → 原生消费者 → 释放”追踪。分别核对成功响应、错误对象、回调委托与请求宿主，不只查成功路径。
- 托管闭包保留包装，不等于保留包装内地址指向的原生对象；IntPtr 非零不证明对象存活。`__bridge` 转换本身不提供跨等待期间的持有；持有必须在原有效期结束前建立，不能等出队后才补救。
- AndroidJavaObject、JNI global/local/weak reference、Objective-C strong/retain/borrowed pointer 分开核实；有包装不等于安全，继续检查 Dispose、回调后的自动释放和 SDK 契约。不能把 Android 正常、编辑器正常或 C# 替身测试通过当成 iOS 安全证据。
- 若新增原生持有，核对成功、失败、策略拒绝提前 return、取消、队列丢弃和异常时的平衡释放；既查过早释放，也查重复释放与泄漏。未知 SDK 内部所有权必须保留待验证，不能仅凭缺少显式 retain 确认 use-after-free。
- 分开验证线程正确性和对象存活：切到主线程只解决执行线程，排队可能扩大对象失效窗口。检查 Unity／UI 调用的线程、原生线程要求、跨线程共享状态，以及主线程同步等回调而回调又等待主线程的互等。

<a id="c3-ads"></a>
## C3 广告入口与恢复

- 按项目实际格式覆盖初始化／授权 → 首次预加载 → 后续重试 → 展示 → 奖励／关闭／失败 → 重新加载／销毁。确认首次标志是每次进程启动还是首次安装；初始化预加载可在玩家未点击广告时触发原生链路。
- 对实际发布平台分别核对编译分支、SDK 包装、回调线程和对象类型；有多层竞价／聚合 SDK 时追踪层间对象交接。只在可达入口展开 Banner、插屏、激励等格式，不默认所有 SDK 行为相同。
- 对收益、埋点、奖励、关闭等回调检查实际订阅者、执行线程、顺序契约及异常传播；确认上报异常是否会跳过奖励、音频恢复、输入解锁或初始化完成标记。
- 对 LockTouch／暂停／加载遮罩／等待回调，明确获取与释放责任；核对成功、展示失败、无奖励关闭、库存失效、异常、晚到／重复回调、窗口退出的可达分支。解锁在可抛调用之后时检查 finally 或等价保证；外层 catch 不会自动恢复业务状态。
- 按最相关窗口验证：首次加载成功／失败、排队期间策略变化或对象失效、展示前库存变化、广告中切后台、关闭与奖励时序、退出后旧回调。以 SDK 实际契约确定允许顺序；不凭空假设任意乱序都会发生。

<a id="c4-validation"></a>
## C4 最小验证与证据沉淀

- 有崩溃材料时先核对目标版本、设备／系统、异常类型、出错线程及符号化栈；区分非法内存访问、未捕获异常、看门狗与内存终止。用户无法提供日志时继续静态追踪与最小实验，不无限追问，也不宣布假设已确认。
- 所有权疑点用原生生命周期实验、Zombies／ASan 或带对象产生／持有／释放／消费记录的对照包验证；故障注入用于确认异常后状态是否恢复。普通 GC 对象替身不能验证原生生命周期，注入异常不能证明真实 SDK 会抛异常。
- 分开报告：用户观察到的现象、代码闭合的机制、实验覆盖范围、真机尚缺的证据。复现非必现时关注首次调用与时序窗口；不得把零次失败的一次运行表述为风险消除。
- 验证或修复对照一次只改变一个关键机制，覆盖成功和失败两条交接路径、提前返回的释放及后续重试；涉及启动／SDK 更换时再补 F3 覆盖升级检查。没有运行目标平台时不宣称该平台通过。
- 按既有地图规则保存已核实的入口、平台所有权／线程边界、历史高风险触发模式、严重度与证据状态、最小验证方法及未闭合项；记录 revision，不把项目特定推测写成全局定论。下次相关改动先检索这些条目，SDK 版本、桥接、派发或释放方式变化时定向重核。
