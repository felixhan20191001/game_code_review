# 活动周期、资源与奖励

适用于受时间或阶段驱动的活动，以及扣除、购买、奖励、补发和领取流程。以下是审查维度，具体业务状态、顺序和规则从当前项目确认。

<a id="a1-activity"></a>
## A1 活动生命周期与轮次

- 联合查看开放条件、参与状态、进度、结束、结算、领奖／展示、冷却与下一轮；实现可能分散在多个对象，并不一定有统一活动基类。
- 明确时间来源、边界包含关系、轮次身份，以及登录时和运行中由谁更新状态；覆盖跨日、离线到期、前后台切换和结束时仍操作旧界面的交叉点。
- 检查每个阶段的进入、停留、退出和重复进入条件；未报名、未开始、主动退出、失败、完成应按各自规则处理。
- 区分业务完成与界面关闭；跳过／中断展示、重启或错过触发时机后，结算与下一轮仍应按需求可达。
- 对互斥、轮转或共享分组，追踪前置活动不能开启或结束时如何影响后续；配置新增、删除、重排时确认旧存档对应的阶段含义。
- 界面、红点、入口和后台状态变化是否一致；过期操作与旧轮次回调不能错误影响新轮次。

<a id="a2-rewards"></a>
## A2 资源扣除、奖励提交与恢复

沿实际实现标明各节点，不要求项目采用固定顺序：

| 节点 | 核对内容 |
|---|---|
| 资格与价格 | 所有实际入口采用正确条件、额度和适用范围；拒绝后没有未经允许的副作用 |
| 扣除／到账 | 唯一业务提交点在哪里；失败或取消时哪些操作应保留、回滚或补偿 |
| 去重与领取记录 | 重复点击、请求、平台回调和重试如何识别同一次业务；标记与资产变化是否一致 |
| 展示确认 | 展示池、动画数字和真实余额是否分离；再次展示不能直接判为再次到账 |
| 持久化与恢复 | 资产、领取标记和轮次何时真实保存；中断后读到哪些组合、恢复做什么 |

- 在适用节点之间考虑中断，核对恢复后不重扣、不重发、不漏发，也不会永久停在处理中。
- 同一业务的重复回调与不同业务的合法连续奖励分开判断；有去重字段不等于所有入口实际使用它。
- 广告、购买或服务端请求的成功、失败、取消、超时及晚到结果，按当前接口约定追踪；没有外部证据时不臆测 SDK 行为。
- 广告专项同时按 [C3 广告入口与恢复](stability-sdk-review-checklist.md#c3-ads)检查初始化和原生交接；不以奖励逻辑正确替代广告稳定性审查。
- 本地保存、远端确认、离线补偿及多份存档之间的边界，补查 [F3 存储边界](framework-data-review-checklist.md#f3-storage)。
- 资源异常使用实际账户、数量与保存证据判断，不仅依据日志、界面变化或函数命名。
