# Game Code Review · 游戏代码审查技能

给 AI 一份策划／需求文档和可访问的游戏工程，帮助它沿真实代码链路检查：**实现是否符合预期，正反逻辑是否完整，玩家会不会遇到异常、资源损失或流程阻塞。**

默认用中文输出，面向策划、测试和非专业游戏程序员：先讲玩家会遇到什么，再说明复现方法、验证状态和代码证据。支持不同游戏项目，不固定某款游戏的配置表、AB 读表方式或玩法调用链。

这是供 AI Agent 读取的技能文件，需要宿主能够读取项目源码及技能引用文件。它本身不包含游戏运行环境或自动游玩工具；静态分析与实际复现会分别标明。

## 能帮你检查什么

| 场景 | 重点 |
|---|---|
| 对照策划文档验收 | 拆解需求条件、触发与效果，核对允许／禁止／例外行为及跨步骤约束；需求不清楚时单独列出 |
| 功能审查与改动回归 | 追踪完整相关实现及共享依赖；Git diff 辅助定位，不取代需求范围 |
| 状态机与异常操作 | 连点、重入、事件竞争、暂停、退出、中断恢复、等待状态无法退出 |
| 活动、道具与奖励 | 活动周期、效果叠加与撤销、扣除／到账次数、持久化和恢复、新老功能耦合 |
| 广告、SDK 与稳定性 | 启动、平台桥接、回调生命周期、崩溃／闪退／卡死、升级兼容 |
| 埋点上报 | 触发时机、字段取值、重复／漏报，以及业务动作与统计记录是否一致 |
| 多语言与字体 | 内置只读脚本检查翻译表、参数、富文本、静态字库和明确 Key 引用；Agent 补充有效路径、玩家影响和中文报告 |
| 已知问题跟进 | 持久编号、去重、忽略／暂缓、修复复核、归档与复发追踪 |

审查按问题类型选择对应清单。简单问题只追踪相关约束和直接依赖；复杂功能才展开必要的规则依赖，不要求每次重建完整关系图。上游问题导致下游无法验证时，会标明受阻范围，不直接把下游都判成 Bug。

## 安装

### Codex：让安装技能处理

在 Codex 中发送：

```text
使用 $skill-installer 安装 https://github.com/felixhan20191001/game_code_review
仓库根目录就是技能目录，请将技能目录命名为 game-code-review。
```

安装时保留整个目录，包括 `references/`、`assets/`、`scripts/` 和 `agents/`，不要只复制 `SKILL.md`。新技能未出现时重启 Codex，再通过技能选择器或 `$game-code-review` 确认能找到它。Codex 支持从其他仓库安装技能并自动发现变化，参见 [官方技能文档](https://learn.chatgpt.com/docs/build-skills#install-curated-skills-for-local-use)。

### Codex：手动安装

以下命令适用于 macOS／Linux，需已安装 Git。使用当前官方文档列出的用户级目录 `~/.agents/skills`，即可在多个项目中使用。参见 [本地技能加载位置](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills)。

```sh
mkdir -p "$HOME/.agents/skills"
git clone https://github.com/felixhan20191001/game_code_review.git \
  "$HOME/.agents/skills/game-code-review"
```

目录中应直接包含 `game-code-review/SKILL.md`。已有安装时更新原目录即可；若当前环境已经从 `~/.codex/skills` 等位置识别了本技能，沿用该位置，避免安装两份同名技能。

也可从仓库页面选择 **Code → Download ZIP**，解压后把包含 `SKILL.md` 的目录命名为 `game-code-review`，放入宿主支持的技能目录。

### 其他 AI Agent

若使用 Grok Build 或其他支持技能文件的 Agent，按该工具的安装方式导入完整目录；若只能读取本地文件，可明确让它读取 `SKILL.md`，并按需读取引用清单。不同宿主的技能发现方式和命令支持不同，本仓库不假定它们共用 Codex 的安装路径。

### 配套技能

本仓库只包含 `game-code-review`，以下技能需要单独获取和安装，可向分享者获取：

| 技能 | 何时需要 | 未安装时 |
|---|---|---|
| `project-code-map` | 自动建立／更新项目代码地图，并按统一规则定位项目外问题台账 | 继续直接审查源码；台账可使用用户明确指定或已确认的路径，没有可靠位置时说明限制 |
| `test-case-five-columns` | 用户另外要求生成、整理或导出测试用例 | 普通问题报告仍可使用；生成五列用例前需补齐该技能 |

配套技能不会被本技能自动下载安装。仅做代码审查不需要先生成测试用例。

## 使用方式

先让 Agent 能访问目标游戏工程，再提供需求文件、功能范围或问题现象。需求文档最好注明版本；诊断问题时补充平台、游戏版本、触发操作和已有日志。

### 开启、关闭与自动调用

| 输入 | 效果 |
|---|---|
| `/game-code-review` | 在当前对话持续使用本技能处理后续游戏审查相关任务 |
| `stop-review` | 关闭当前对话中的自动使用；普通问题仍正常回答 |
| `恢复 game-code-review 的自动调用` | 恢复按任务相关性选择技能 |
| `仅本次使用 game-code-review，检查……` | 只用于本次任务，不改变原会话模式 |

不输入命令时，新会话默认按任务相关性自动选择；能否被选中还取决于宿主是否发现并启用了该技能。Codex 中也可以通过 `$game-code-review` 显式选用。

`/game-code-review` 和 `stop-review` 是技能约定的对话指令，需宿主将内容传给 AI，不表示本仓库注册了所有工具的原生命令。若未识别，可先显式选中技能，再用自然语言说明开启／关闭意图。持续模式只覆盖当前对话，新会话默认恢复自动；问题台账则可通过外部文件跨对话读取。

### 可以直接复制的请求

**对照需求文档：**

```text
/game-code-review
请对照我附上的活动需求文档，检查当前工程的完整实现。
重点看开放条件、领奖、重复操作和退出后恢复，正反路径都要核对。
不要修改业务代码。问题请用策划和测试能看懂的语言说明，
能映射成玩家操作的写出手动复现步骤。
```

**检查版本改动：**

```text
/game-code-review 检查当前分支相对主分支的改动及相关公共依赖，
重点看广告返回、奖励到账和输入状态恢复，标明覆盖的平台和未验证部分。
```

**多语言专项：**

```text
使用 game-code-review 检查当前项目的多语言，包含静态字库覆盖和 Key 引用。
不要修改游戏文件；给出中文问题报告，区分确定数据差异、待验证风险和未覆盖范围。
```

专项使用内置 `scripts/check_localization.py`，需要 Python 3.11+ 及 `scripts/requirements-localization.txt` 中的依赖。让 Agent 按 [多语言专项说明](references/localization-review.md) 在项目外复用或建立环境和配置即可；无需接入 Unity 插件。普通审查不会因此启动多语言扫描。

**复核已知问题：**

```text
复核当前项目台账中的 ISSUE-0003 是否已解决。
检查原触发条件和影响范围，证据充分时移出当前表并保留历史。
```

**记录处理决定：**

```text
将当前项目的 ISSUE-0007 标记为已忽略，理由是只影响测试环境。
ISSUE-0008 暂缓到下个版本；其他问题的决定保持不变。
```

示例编号需替换为实际台账编号。后续也可直接追问“继续看边界情况”“这个问题修完了吗”。

## 会得到怎样的报告

每个问题依次包含：

1. **标题与严重程度**：用玩家现象命名，说明影响。
2. **问题描述**：什么条件下出现、会看到什么、有什么后果。
3. **预期与实际**：给出需求依据；未运行时写明根据代码推导。
4. **复现前提与手动步骤**：操作可达且有依据时给出编号步骤；需特殊数据或内部回调时注明工具／技术协助要求。
5. **验证状态**：区分已实际复现、用户／测试已复现、代码链路明确但尚未实测、仍需验证。
6. **原因与代码证据**：末尾用通俗解释搭配文件链接和行号。

需求核对结果和未覆盖项放在问题列表之后。需求歧义只保留在本次报告，不写入问题台账；有具体证据的待验证风险与确定缺陷分开统计。没有发现确定问题，不代表游戏已完成全面运行验证。

## 代码地图与问题台账存在哪里

配套 `project-code-map` 可用且允许写入时，默认使用项目外目录：

```text
~/.local/share/project-code-maps/<项目名>-<路径哈希>/
├── INDEX.md          # 代码地图入口，其他地图文件按需生成
└── review/
    └── issues.md     # 当前问题、用户决定及已结束记录
```

地图在首次审查时按当前目标建立，相关结构或关键链路变化时增量更新；已有内容经源码核实后复用。问题台账每次实际审查都会读取并简短提醒，正式问题自动入表、去重，具体风险单独标记。

- 处理决定分为 **待决策／需解决／暂缓／已忽略**；AI 不自行替用户忽略问题。
- 同条件的已忽略问题不重复展开；影响扩大或忽略理由失效时提醒重新评估。
- 确认修复后移出当前表并保留验证依据与历史；部分平台修复不代表整个问题关闭。
- 同一问题复发时沿用原编号；一般猜测和仅因上游阻塞而未验证的条目不作为新 Bug 入表。

这些文件不写入游戏仓库，因此清理游戏项目的本地改动不会一并删除它们；源码回退后仍需重新核对记录。不同克隆目录分别识别项目。其他 Agent 只有能访问相同外部文件并遵循相同定位规则，才能复用记录；不会自动跨设备同步。

业务源码默认只读，但项目外地图和台账允许按上述规则维护。若连外部文件也不希望写入，请明确说：**“本次仅只读，不要写任何文件。”**

## 更新技能

通过上述 Git 克隆方式安装时，在安装目录执行：

```sh
git -C "$HOME/.agents/skills/game-code-review" pull --ff-only
```

若安装在其他位置，将路径替换为实际目录。有自己修改的技能文件时先检查并保留改动，再处理更新；ZIP 安装则重新下载，保留本地定制后更新技能目录。项目外地图和台账独立于技能安装目录。
