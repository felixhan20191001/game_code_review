# Project Code Map

为后续 AI 分析生成可检索、可核实、可局部更新的代码导航。默认中文说明，保留真实代码符号；所有产物统一为 Markdown，图使用文内 Mermaid 代码块。地图帮助选择阅读位置，业务结论仍以当前源码和需求为准。

## 按任务选择入口

| 当前任务 | 行为与阅读入口 |
|---|---|
| 首次建立项目结构／代码地图 | 识别范围，阅读[产物结构](references/map-format.md)，生成概览与已核实的关键链路 |
| 梳理指定功能、数据流或状态转换 | 只追踪目标及真实依赖；阅读[关系证据](references/evidence-and-updates.md#evidence)，补充对应链路 |
| 使用已有地图定位代码 | 先读索引与时效信息，再读相关链路并回查源码；使用下方“定位模式” |
| 更新地图、文件迁移、公共框架或功能变更 | 阅读[增量更新](references/evidence-and-updates.md#updates)，重查受影响关系与索引 |
| `game-code-review` 发起地图辅助请求 | 按调用方指定的项目、目标和变化依据进入建图／补充／更新模式，完成后返回原审查 |

普通定位请求不自动变成全项目建图或写文档任务。用户明确要求生成／更新，或 `game-code-review` 按其联动规则发起辅助请求时，写相应导航文件，无需另行确认；当次明确只读或禁止写文件的要求优先。不要借建图修改业务代码、项目指导文件、全局配置或建立后台任务。

**审查辅助模式：** 首次建图覆盖概览、索引与本次目标链路；已有地图只补充或更新调用方确定的受影响范围。返回索引路径、维护范围及仍未核实的关系，由调用方继续代码审查；本技能不再次启动 `game-code-review`，也不将地图完成视为审查完成。

## 位置与规模

- 默认存到项目目录外：`~/.local/share/project-code-maps/<项目名>-<路径哈希>/INDEX.md`。生成、定位与更新前都按[存储与项目识别](references/storage.md)计算同一位置，核对项目归属；不能仅按项目名称匹配。
- 用户明确指定位置时遵循指定；仓库内已有地图可作只读参考，需要维护时默认写到外部位置。不要自动删除旧文件、修改 `.gitignore` 或向项目添加地图入口文件。
- 小项目可在一个 `INDEX.md` 内完成总览、索引和链路。大型项目保留简短入口，按需拆成 `modules/<模块>.md`、`flows/<链路>.md`；全部仍为 Markdown，不另维护 HTML、图片或 JSON 副本。
- 按项目／子系统分开记录范围。只处理用户指定的项目，不把相似项目的结论复用为事实，也不自动扫描其他仓库。
- 首轮默认建立全局概览与最能解释项目运行方式的代表链路；用户指定完整功能范围时逐项覆盖。未深入模块列入覆盖表，不以目录盘点冒充全项目逻辑已核实。

## 建图流程

1. **建立基线。** 确认项目根、项目指导、源码边界和已有文档；记录当前 revision 与工作区状态。用 `rg --files` 盘点入口、构建／程序集配置和主要源码目录，默认略过缓存、构建产物及第三方实现；实际链路进入这些边界时按需补查。非 Git 项目也能建图，按文件版本核实。
2. **识别真实架构。** 从启动／装配入口、注册处和代表模块确认职责、状态拥有者、事件传播、配置与存储边界。目录名、旧文档和相似实现只作线索；候选模块可列出，但不得标成已核实实现。Unity 等引擎需结合实际场景／资源绑定与生命周期，不能仅搜索普通函数调用。
3. **建立业务索引。** 将业务名称、常用同义词和问题现象映射到模块、入口符号、关键源码与链路页。一个条目应能回答“下一步先读哪个文件、哪个符号、为什么”；不罗列每个类或复制大量源码。
4. **追踪关键关系。** 沿目标入口记录校验分支、状态／资源写入、调用、事件注册与消费、异步恢复、配置读取及保存。只记录实际存在的节点，不预设表结构、AB 规则、引擎或业务调用链。明确来源、去向、条件、同步／异步边界及证据，规则见[关系证据](references/evidence-and-updates.md#evidence)。
5. **形成图与导航。** 先写有依据的节点／关系记录，再据此画分层小图；一图回答一个结构或链路问题，复杂部分链接到子页。总览表示模块关系，流程／时序图表示执行过程，状态图只用于实际状态转换；不得用同一种无标签箭头混淆它们。
6. **核对并交付。** 检查图表与证据是否一致、源码与文档链接是否存在、符号与行号是否匹配，以及未确认边界是否明确。只做静态阅读时注明；没有渲染器则标注 Mermaid 未渲染验证，不为生成导航默认安装依赖。最终给索引路径、覆盖范围和验证限制，不重复整份地图。

## 定位模式

1. 按[存储与项目识别](references/storage.md)找到本项目已有索引，读取范围、版本／工作区状态与业务路由。独立定位时索引缺失就直接搜索目标源码，不先要求用户完成建图；审查辅助请求则按上方对应模式建立或补充地图。
2. 只打开命中的模块／链路页，用文件路径与符号回查当前实现，特别核对入口注册、共享状态和异步边界。源码变化或证据断裂时扩大定向搜索，不强行沿旧图继续。
3. 返回当前可用的入口、相关写入／消费位置和仍缺的证据；后续交给原来的实现、诊断或审查任务继续。使用 `game-code-review` 时，地图只提供定位线索，不替代需求核对或问题证据。
4. 独立定位发现地图过期但任务只要求分析时，在回复中标明受影响条目；用户要求维护或收到审查辅助请求时，按增量更新规则写入。不要把“未画出”当作“代码不存在”。

## 验收标准

- 业务关键词能落到当前存在的源码路径和符号，而非仅目录名称。
- 每条关键调用／事件／数据关系有可回查证据；静态已核实、运行已验证、待确认分别标明。
- 图与索引共享同一组事实，省略细节不改变执行顺序或同步／异步含义。
- 记录项目范围、代码基线、未提交状态、覆盖和缺口；更新不能把未重查内容标成最新。
- 文档互链使用相对路径，源码标识使用项目相对路径与符号；外部地图的源码链接按记录的项目根生成绝对路径，不能相对地图目录查找源码。回复中的本地文件链接使用当前环境的绝对路径。没有已做过的量化对比，不宣称提高了多少速度或准确率。
