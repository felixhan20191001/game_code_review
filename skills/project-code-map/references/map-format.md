# Markdown 代码地图结构

按项目规模裁剪章节，只创建有内容的文件。`INDEX.md` 是默认入口；已有导航有自己的命名时保留，并在最终回复说明入口。不要同时维护含义相同的两套地图。

## 索引必需内容

**基线与范围：** 项目标识、规范化项目根绝对路径、地图入口绝对路径、覆盖的子系统、核实日期、Git revision（可取得时）、相关工作区是否有未提交／未跟踪文件、验证方式。位置规则见[存储与项目识别](storage.md)。非 Git 或旧基线不可取得时如实记录。按文件或功能列出已深入、仅识别入口、未覆盖的范围，避免一个“已完成”标签覆盖全部代码。

**结构概览：** 简短目录职责与模块关系图；区分业务代码、公共框架、生成数据和外部边界。只有导入或构建依赖证据时，图中标为“依赖”，不画成已发生的调用链。

**业务定位表：** 至少含以下信息，可合并同义词，不能仅列文件夹。

| 业务词／问题现象 | 模块职责与状态归属 | 首读入口与关键符号 | 源码位置 | 详情与证据状态 |
|---|---|---|---|---|

源码位置记录项目相对路径、准确符号和核实时行号，方便迁移或行号漂移后搜索。外部地图中的源码链接使用“记录的项目根 + 项目相对路径”得到的绝对路径；路径含空格时用尖括号包裹 Markdown 链接目标。地图各页互链仍相对当前文档目录计算。项目位置变更时先核对归属再重建源码链接；`文件存在`、`类被导入`都不能替代入口可达证据。

**缺口：** 对未找到的入口、缺失依赖、动态选择、未读模块，说明缺少什么、影响哪条链路、下一步应从哪里核实。与已确认实现分开。

## 模块页（需要时）

写清模块职责、业务别名、构造／注册入口、主要状态拥有者、上游调用者与下游依赖，以及涉及的链路链接。只保留当前导航需要的细节；共享机制在一个模块页维护，链路页引用它。

## 链路页

1. **目的与触发：** 业务词、入口、可达前提、适用配置／模式和本页覆盖边界。真实 UI 文案缺失时用有依据的业务动作，不发明按钮名。
2. **基线：** 本链路最近核实的 revision、相关工作区变化与验证方式；索引有统一基线时可引用，局部更新则记录差异。
3. **Mermaid 图：** 选流程、时序或状态图。使用稳定、简短的节点 ID，标签保留业务意义与必要符号。直接关系和待确认关系用不同线型／标签，并给出图例；不要让虚线同时表示“异步”和“证据不足”。
4. **关系证据表：** 为关键关系保留以下字段。图中边可引用关系编号；图内未写出的条件在表中明确。

| 关系编号 | 从 → 到 | 关系类型／执行条件 | 状态或数据变化 | 源码路径、符号与行号 | 证据状态 |
|---|---|---|---|---|---|

5. **分支与边界：** 只记录与目标相关的拒绝、失败、取消、重复和中断出口，以及配置来源、存储提交或外部回调边界。记录实现事实；没有需求依据时不判定这些行为正确或错误。
6. **相关导航与缺口：** 链到共享模块和相邻链路；说明未闭合节点。需要大型展开时拆出子页，保留返回索引的链接。

## 证据状态与使用方式

- **静态已核实：** 当前源码、注册／绑定和相关配置支持这条关系；不等于运行环境已验证。
- **运行已验证：** 实际执行并观察到关系成立；附环境与验证方式，范围不能超出实际观察。
- **待确认：** 只有名称线索、文档约定、缺失的外部实现或不完整的动态选择证据。标明原因，不将该边用于确定性结论。

文档已有人工注释时保留。不要加入密钥、完整账号数据或无关配置正文；导航只记录理解关系所需的结构与位置。
