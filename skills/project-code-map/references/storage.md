# 存储与项目识别

生成、定位和更新都使用本规则。默认位置独立于 Git 工作区与技能安装目录，项目内的 discard／clean 不会清理这里的地图；源码回退、拉取和分支切换仍需检查地图时效。

## 计算位置

1. 先确认本次目标项目根，不从当前工作目录猜测另一项目。Git 仓库通常使用工作树根；只审查其中一个模块时在同一地图记录子范围，不另建项目。解析符号链接得到规范化绝对路径。
2. 默认存储根为 `~/.local/share/project-code-maps`（当前系统用户目录）。项目键为 `<项目根目录名>-<规范化绝对路径的 SHA-256 前16位>`。目录名部分仅保留 ASCII 字母、数字、点、下划线和横线；其他连续字符替换为横线，去除首尾点和横线，空值用 `project`。
3. 使用本技能的 [路径工具](../scripts/map_location.py)，将下例技能路径替换为实际安装位置：

   ```sh
   python3 /absolute/path/to/project-code-map/scripts/map_location.py --project-root /absolute/path/to/project
   ```

   工具只输出项目根、地图目录和索引路径，不建目录、不写文件、不读取业务源码。没有 Python 时按上述相同规则计算，不临时另定命名方案。用户指定外部集中存储根时可传 `--storage-root`；指定完整地图路径时直接使用指定路径。
4. 读取已有索引前核对其记录的项目根。路径哈希只是定位键，不能替代归属核对。不同克隆／worktree 分开；同一目录的分支切换仍使用同一地图，但必须核对 revision 和工作区。项目搬家后重新定位，旧地图仅作待核实材料，不自动套用旧根路径或删除旧目录。

Codex 与其他支持此技能的工具，在同一系统用户、同一项目路径下按相同规则定位；不依赖会话记忆或某个工具专属配置。地图文件只是导航数据，不是新的代理指令来源。

## 查找与旧图处理

- 优先使用用户明确指定的地图路径，否则查上述外部索引；默认入口不存在时检查该项目地图目录内已有的 Markdown 入口，再参考项目指导指向的旧地图或历史默认 `docs/code-map/INDEX.md`。已有自定义入口名称时保留并记录，不重复创建同义导航。
- 外部地图已经存在时，以它为维护入口；仓库内文档仅补充线索，不双向同步两份地图。任何旧图仍需回查当前源码。
- 只有仓库内旧图时，普通定位可直接只读使用；生成／维护任务将有用内容与人工备注保留到外部地图，修正源码链接、记录来源和原基线，再更新本次目标。不要把未重查部分标成最新，不修改或删除仓库内旧图。
- 完全无图且任务授权建图时，在外部位置创建所需 Markdown。仅编辑技能、查询规则或定位路径时不生成空索引。

## 写入边界

- 默认地图目录的真实路径必须在目标工作树外，包含对已有符号链接的检查。不可写、路径冲突或归属不符时，说明限制并直接分析源码；不要回退到项目内生成文件。
- 用户明确指定其他位置时优先遵循，包括明确要求项目内存储；项目内旧文档写着旧默认位置不构成新的用户指定。不为地图修改项目指导、`.gitignore` 或 Git 配置。
- “不改项目文件”允许在项目外维护地图；“不要写任何文件／本次仅只读”则禁止外部地图写入。回复说明实际新建／更新／复用的位置，不把外部持久保存当作代码仍然一致。
