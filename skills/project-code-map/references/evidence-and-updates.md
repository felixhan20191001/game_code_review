# 关系证据与增量更新

<a id="evidence"></a>
## 关系成立需要什么证据

| 关系 | 核实要点 |
|---|---|
| 构建／导入依赖 | 依赖声明、导入或引用能证明关联，不能证明对象被创建或函数被调用 |
| 直接调用／委托／接口派发 | 调用点、目标符号与实际注入／绑定实现；多个候选实现分开记录生效条件 |
| 事件发布与订阅 | 发布点、事件标识、真实订阅注册、处理器及分发实现；检查同步通知、队列与调度边界，不能把发布直接画成消费完成 |
| 引擎生命周期／序列化绑定 | 当前加载入口、场景／资源、继承或变体覆盖及运行时赋值；仅存在组件或资源文件不能证明正在使用 |
| 状态和数据读写 | 状态拥有者、关键读写方及作用域；内存变化、展示、写盘和远端确认分开；名为 Save 的函数也要读实现 |
| 配置与生成数据 | 本项目的来源、加载／选择入口、缓存与消费者；配置文件存在不代表当前调用使用它，不套用其他项目的表名或 AB 规则 |
| 异步／外部调用 | 发起与结果处理、宿主／调度、取消和对象生命周期、局次／账号归属；外部实现缺失就停在可证明边界 |

搜索找到旧实现但未找到注册时，只能标为“当前已查入口未接入”。反射、字符串路由、接口与资源驱动路径需要进一步核实，不从一次搜索未命中推断全项目无调用。

主链路必须能从已识别入口开始；跨模块关系保留必要中介和条件。关键等待、事件排队、存储边界不能因画图简化而消失。地图描述实际实现，不将需求流程、期望修复或相似项目画成当前事实。

<a id="updates"></a>
## 增量更新

1. **读取旧基线。** 按[存储与项目识别](storage.md)核对索引记录的项目根／子系统、每条链路的 revision、核实范围与未提交状态。地图默认存放在项目外，归属由记录的项目根判断。归属无法确认、缺失基线或只标日期时，先按目标回查源码，不能将旧图当作当前事实。
2. **找实际变化。** Git 项目比较可用旧 revision 与当前 HEAD，并包含已暂存、未暂存和与目标相关的未跟踪文件；识别新增、删除和重命名。只比较提交记录会漏掉工作区变化。排除地图自身产物产生的无关变更。
3. **处理无法比较的状态。** 旧图基于脏工作区而未记录对应内容、旧提交不可用，或没有 Git 时，逐项重读目标链路的源码、绑定与注册；可用已记录的内容指纹缩小范围。HEAD 相同、文件名相同或修改时间相近均不足以证明内容与关系未变。
4. **扩展影响范围。** 除直接改动的节点，还查引用它的调用方、事件注册／消费者、公共状态读写方与配置选择；公共调度变化可能影响多条链路。按真实依赖选择重查对象，不能只修图中的文件名。
5. **局部修订。** 更新受影响节点、关系证据、条件分支、图和业务索引；文件迁移时修复入链／出链及反向链接。保留无关内容与人工备注，避免整目录重建或删除用户文件。删除不再成立的关系时说明原链路去向或当前未找到的边界。
6. **记录检查边界。** 更新已重查链路的基线；未重查部分保留原基线，或标为待复核。共享依赖有变化但尚未补查的链路明确标记，不统一盖上“全部最新”。

## 完成前核对

- 从索引选取本次涉及的业务词，确认能找到正确入口、关键状态写入／消费方及证据；重点回读变更相关的关系，而非仅检查链接存在。
- 验证文档互链、项目相对源码标识及对应的绝对链接，核对符号与行号；检查重命名／删除后是否残留旧指向，源码链接不能误指到外部地图目录。
- 核对关系表与 Mermaid 图一致，条件、异步边界及不确定状态未在图中丢失；静态语法检查与实际渲染分开报告。
- 没有实际执行就只称静态导航；生成地图本身不代表功能验收，也不保证下一次调用必定加载地图。后续任务需先找到索引并核实相关源码。
